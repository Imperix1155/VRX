# 5. Renderer

Part of the [internal API catalog](../INTERNAL-API.md). The code is the source of truth: read the file a row names before relying on it.

The renderer lives in `src/renderer/src`. Its contract is [`src/renderer/AGENTS.md`](../../src/renderer/AGENTS.md). Four rules apply to every surface below:

- TanStack Query owns server and cache state. Zustand owns view state only. Stores never import each other.
- Every bridge consumer checks that `window.vrx` (and the method it needs) exists, so tests and the design guide degrade instead of throwing.
- App-wide subscriptions are mounted once. Do not add a second listener for an event that an app-lifetime hook already handles.
- User-facing copy goes through i18next, with the key in every locale.

Boot order: [`main.tsx`](../../src/renderer/src/main.tsx) installs `installDocumentDropGuard` and `installHeldEnterGuard`, then renders `PersistQueryClientProvider` (`buildPersistOptions`, `onPersistRestore` on restore) around the top-level `ErrorBoundary` and `App`. [`App.tsx`](../../src/renderer/src/App.tsx) mounts `useSettingsPersistence`, `usePlatformFilterSettings`, `useApplyTheme`, `useApplyGlow`, `useLiveFriendEvents`, `useLinkedProfileEvents`, `useActivityEvents` and `useInboxEvents`, calls `notifyRendererHydrated` once settings hydrate, and routes a hot-instance notification click (`onNavigateToDashboard`) to Hot Instances. It shows `BootSplash` until settings hydrate, then `SetupWizard` while `setupPending` is true, `AppShell` when either platform is `authenticated` or `error` (or its auth check failed), `BootSplash` while auth is still pending, and `LoginScreen` otherwise. [`AppShell`](../../src/renderer/src/components/AppShell.tsx) mounts `useHiddenPageFallback` (a hidden active page falls back to the Dashboard before paint), `useExploreCoordinator` and the single `JoinConfirmDialog`.

## Queries (TanStack Query)

### Query keys and what changes them

| Key | Observer and cadence | Written, invalidated or cleared by |
| --- | --- | --- |
| `['auth-status', platform]` | `useAuthStatus`. `staleTime` Infinity (page mounts never re-check), `retryOnMount: false`. Only an `error` status re-checks, every `AUTH_ERROR_RECHECK_MS` (60 s) while the window shows; while it is hidden, only an `unreachable` one. Not persisted. | Invalidated by `useAuthFlow` after a successful sign-in or 2FA, by `AccountCard` Disconnect and Retry, and by `useLiveFriendEvents` on `auth-invalidated` and on `connection: live` while that platform is quarantined. `useAuthFlow` writes `unauthenticated` when main reports `sessionCleared`. |
| `['friends', platform]` | `useFriends`. Enabled only while that platform's auth state is `authenticated` or `error`. Cadence from `settings.reconcileInterval`, jittered ±10%; `manual` means no interval and infinite staleness. `networkMode: 'always'`. Persisted. | Live deltas patch it. Invalidated on `connection: live` (not quarantined), `roster-changed`, identity boundary, quarantine release, cache restore and `AccountCard` sign-in. Set to `[]` on `auth-invalidated`, identity boundary, Disconnect, and when auth settles signed out over a cached roster. `useJoinInstance` refetches once after `target-changed`: after a direct Join only while the cache still shows the place main turned down, after Confirm unless the cache already shows a new place to review. |

| `['linked-profiles']` | `useLinkedProfiles`. `staleTime` Infinity, no retry, structural sharing through `retainNewestLinkSnapshot`. | `['app-background']` | `useAppBackground` (`AppBackdrop`, Settings, setup). `staleTime` Infinity, no retry, no refetch. `chooseAppBackground` and `clearAppBackground` write the result in place. Not persisted. |
| `['inbox']` | `useInbox` (Sidebar badge, Inbox page). `staleTime` Infinity, `networkMode: 'always'`; `useInboxEvents` invalidates on `inbox-changed`. Not persisted. |
| `['friend-note', platform, friendId, epoch]` | `useFriendNote`. `staleTime` Infinity. An empty `friendId` uses the inert key `['friend-note-disabled']`. Not persisted. | A successful save writes the saved note. A `stale` save reply refetches the exact key. Identity boundary cancels and removes every `['friend-note', platform]` query and advances the epoch. |
| `['alert-picks', platform, accountId]` | `useAlertPicks`. Enabled only while signed in; `staleTime` Infinity. Not persisted. | `useSetAlertPicks` writes the change first and, after any refused save, refetches and answers once the refetch settles. Identity boundary cancels and removes every `['alert-picks', platform]` query. |
| `['favorite-friends', platform, accountId]` | `useFavoriteFriends` (Friends list, friend details star). Enabled only while signed in; `staleTime` Infinity. Not persisted. | `useSetFavoriteFriends` writes the change first (both accounts of a linked person) and refetches after any refused save. Identity boundary cancels and removes every `['favorite-friends', platform]` query. |
| `['game-favorites', platform, accountId]` | `useGameFavorites` (friend and world star panels, Friends list Favorites section, Explore → Favorites, which asks again on each show for fresh references). Not persisted. | `useSetGameFavorite` writes the change first and puts back main's answer, or the old groups after a refusal. `refreshGameFavorites` (Explore Refresh) keeps a ready list when main refuses. Identity boundary cancels and removes every `['game-favorites', platform]` query. |
| `['favorite-worlds', platform, accountId]` | `useFavoriteWorlds` (world sheet star, Explore → Favorites, which rereads on each show so its references are fresh). Same client and account rules. Not persisted. | `useSetFavoriteWorld` writes the change first and refetches after any refused save. Identity boundary cancels and removes every `['favorite-worlds', platform]` query. |
| `['activity']` | `useActivity` (Activity page) and `useActivityForFriendsOrder` (the Friends Recent order). `staleTime` Infinity, no retry, `networkMode: 'always'`; `useActivityEvents` invalidates on `activity-changed`. Not persisted. |
| `['avatar-library', platform, accountId]` | `useAvatarLibrary` (Avatars page). Fresh for 5 minutes (`AVATAR_LIBRARY_STALE_MS`), kept for the session, no retry or reconnect refetch. A failed refresh keeps the list that loaded. Not persisted. |
| `['avatar-details', platform, accountId, avatarId]` | `useAvatarDetails` (avatar sheet). Same timing as the library. Not persisted. |
| `['current-avatar', platform, accountId]` | `useWornAvatar` (Dashboard Wearing now). Same freshness as the library; the newer of this and the library's `current` wins. Not persisted. |
| `['home-world', platform, accountId]` | Written by `setHomeWorld` after a successful press and read by `useHomeWorldId`; no query function, kept for the session. |
| `['own-profile', platform, accountId]` | `useOwnProfile` (Edit profile). `staleTime` 0 and `gcTime` 0 (main reuses an answer under 30 s), no retry or refetch on focus or reconnect. |
| `[kind, platform, accountId, detail]` | `communityQueryKey` for `profile`, `profile-worlds`, `profile-groups`, `community-search` and `world-list` (2 minutes fresh), `players-online`, `my-groups` and `relationship`. Fresh for `COMMUNITY_CACHE_MS` (5 minutes) otherwise; never refetched on a timer, focus or reconnect; no retry. Not persisted. |

Only the `friends` namespace is persisted (localStorage key `vrx-query-cache`). Auth status, Explore, linked profiles and notes are read again each session.

## Hooks

### App-lifetime hooks (mount once)

| Symbol | File | Purpose |
| --- | --- | --- |
| `useSettingsPersistence` | [`useSettingsPersistence.ts`](../../src/renderer/src/hooks/useSettingsPersistence.ts) | Loads settings on boot (two backoff retries, 250 ms then 500 ms, for `rate_limited`; any other failure hydrates, then throws to the ErrorBoundary). Keeps edits made during the load. Sends the full snapshot whenever dirty. After a `fallback` load it sets `loadFallback` and sends only edits until a save adopts the real file. A `newerFile` load sets `newerFile`. Rule: no save before the load lands; a failed save stays dirty. |
| `usePlatformFilterSettings` | [`usePlatformFilterSettings.ts`](../../src/renderer/src/hooks/usePlatformFilterSettings.ts) | After hydration, keeps `useFriendsStore.platformFilter` and `settings.platformFilter` in step in both directions, so neither store imports the other. |
| `useApplyTheme`, `applyTheme` | [`useApplyTheme.ts`](../../src/renderer/src/hooks/useApplyTheme.ts) | After hydration, sets `data-theme="light"` on `<html>` for Light or for System with a light OS preference, and removes it otherwise. System follows OS changes. `applyTheme(theme, prefersLight)` is the pure applicator the guide reuses. |
| `useApplyGlow`, `applyGlow` | [`useApplyGlow.ts`](../../src/renderer/src/hooks/useApplyGlow.ts) | After hydration, sets `data-glow` to `off`, `muted` or `vivid`; `standard` removes the attribute. `applyGlow(glow)` is the pure applicator. |
| `useLiveFriendEvents` | [`useLiveFriendEvents.ts`](../../src/renderer/src/hooks/useLiveFriendEvents.ts) | Bridges `onFriendEvent` and `onIdentityBoundary` into the roster cache, and buffers the CVR presence snapshot until the roster lands. See the paragraph below. |
| `useExploreCoordinator`, `eligibleExploreAutomatic`, `clearExploreAutomaticGate` | [`useExploreCoordinator.ts`](../../src/renderer/src/hooks/useExploreCoordinator.ts) | The only renderer trigger for Explore discovery, mounted by AppShell. See the paragraph below. Rule: no timers or polling; main owns every wire budget. |

`useLiveFriendEvents` applies friend deltas through `applyOrderedFriendEvent`. `connection: live` invalidates that platform's roster. `roster-changed` invalidates it once a burst of them pauses for `ROSTER_CHANGED_SETTLE_MS` (400 ms), or every `ROSTER_CHANGED_MAX_WAIT_MS` (3 s) while they keep coming; a waiting re-read is dropped at sign-out and at an identity boundary. Any connection change drops the buffered CVR snapshot. An identity boundary clears VRChat replay state, the buffered snapshot and that platform's note queries, sets the roster to `[]`, invalidates it, and persists. `auth-invalidated` quarantines the platform: the roster is forced to `[]`, in-flight fetches are cancelled, auth is re-checked, and every later event for that platform is dropped. Only an `authenticated` auth-status lifts the quarantine; socket-open is not proof of re-auth. When auth settles to a signed-out state over a restored roster, that roster is also cleared.

`useExploreCoordinator` counts Explore as relevant while the window is visible and either the Explore page is open or the Dashboard is open with Popular now on. It declares the active platforms (in filter scope, signed in, with an account ID) through `setExploreActive`. Only after main accepts does it admit images and send `automatic` requests. A platform qualifies when its snapshot is missing, stale or at least 60 s old, and its last automatic attempt for that account was at least five minutes ago. Visibility, focus, `online` and `connection: live` wake it. Identity boundaries and `auth-invalidated` clear the gate and the platform's cache. AppShell unmount declares no platforms.
