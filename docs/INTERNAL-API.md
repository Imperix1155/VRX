# VRX internal API catalog

Look here before you build. This catalog lists every IPC channel, bridge
method, live event, hook, store, parser, service, and shared constant that
already exists. If what you need is here, use it instead of building another.
If you add or change a surface, update its row in the same PR.

The code is the source of truth. Every row names its defining file; read that
file before relying on a row. Rules that apply to a whole directory live in
the `AGENTS.md` files; this catalog is the index card, not the essay.

## 1. Renderer bridge: `window.vrx`

The sandboxed renderer reaches the main process only through `window.vrx`.
[`src/preload/index.ts`](../src/preload/index.ts) builds the object and exposes it with
`contextBridge`. [`src/preload/index.d.ts`](../src/preload/index.d.ts) types it as `VrxBridge`.
Every invoke method is a typed projection of one `IpcInvoke` channel, and section 2 names the
method for each channel. Every `on…` method subscribes to one push channel and returns an
unsubscribe function.

Rule: the global is declared optional (`vrx?: VrxBridge`) because unit tests, Preview and the
design guide run without the preload. Every caller must handle a missing bridge or method. The
bridge forwards requests and push payloads unchanged. It adds no authority or policy; its only
transformation is the rate-limit error below.

| Symbol                      | File                                      | Purpose                                                                                                                                                                                                                        |
| --------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `VrxBridge`                 | [`index.d.ts`](../src/preload/index.d.ts) | The bridge type: 39 invoke methods, one notify method and seven subscriptions, all derived from `@shared/ipc`. The design guide's fixture bridge implements the same type with synthetic data (section 8).                     |

## 2. IPC channels

[`src/shared/ipc.ts`](../src/shared/ipc.ts) is the single typed map: `IpcInvoke` (renderer asks,
main answers), `IpcEvents` (main pushes) and `IpcNotifications` (renderer sends, no reply).
Handlers live in [`src/main/ipc/`](../src/main/ipc/), one file per domain. Add a channel only when
no listed channel fits, and change the shared type, preload, registration, handler tests and this
catalog together.

Rule (sender trust): [`registerIpcHandlers`](../src/main/ipc/index.ts) is the only registration
point. While the domain modules register, it wraps `ipcMain.handle` so each invoke runs
[`isTrustedIpcSender`](../src/main/ipc/security.ts) first, then the channel's rate limiter, then
the handler. An untrusted sender gets `Untrusted IPC sender` and spends no budget. Each handler
repeats the trust check and validates its request before use. The check admits only the exact
Vite dev-server origin in development, or the top-level `out/renderer/index.html` document in
packaged builds and built preview. Subframes and other local files fail. Registration removes
electron-store's unused `electron-store-get-data` listener, and electron-log is imported from its
Node entry (`electron-log/node`), which installs no IPC listener. The registered surface is exactly the 43 invoke channels below plus
`renderer-hydrated`.

Rule (rate budgets): `IPC_RATE_LIMIT_BUDGETS` in [`rate-limit.ts`](../src/main/ipc/rate-limit.ts)
holds one timer-free sliding window per process and channel on a monotonic clock. A limiter fault
fails open. An exceeded budget logs one `IPC rate limit exceeded` warning per window with the
channel name only. Structured channels keep their result shape on denial: `login`,
`verify-2fa` and `import-session` return `{ ok: false, needs2fa: false, error: 'rate_limited' }`, while
`join-instance`, `join-explore-room`, `self-invite`, `switch-avatar`, `set-friend-note`, `set-alert-pick`, `get-linked-profiles` and
`change-linked-profile` return `{ ok: false, reason: 'rate-limited' }`. Every other invoke rejects
with `rate_limited`. No denial carries retry timing or request data. These budgets are local; the
platform wire limit is the admission queue in section 4.

The updater handlers delegate to `UpdaterService` in [`src/main/updater.ts`](../src/main/updater.ts).
The Explore handlers validate with strict Zod schemas (references 1 to 128 chars) and delegate to
[`ExploreService`](../src/main/services/exploreService.ts). The avatar handlers validate with strict
Zod schemas and delegate to [`AvatarLibraryService`](../src/main/services/avatarLibraryService.ts),
or for `get-current-avatar` to [`CurrentAvatarService`](../src/main/services/currentAvatarService.ts).
The community handlers validate with strict Zod schemas and delegate to
[`CommunityService`](../src/main/services/communityService.ts).

`get-friends` ordering: the handler captures a `LocationAuthority` seed revision before the read,
seeds the authority from each physical read in `FriendRoster.seeds`, records the reconcile time in
`AppStatusService`, and hands `FriendAlerts.seedRoster` the authority's merged rows, so a live
removal that landed during the read wins. VRChat responses add `provenance`: `baseRevision`,
deduplicated `coveredIds` for a partial read, and `overrides` naming rows replaced by a follow-up
read. Rule: only a `complete` roster may reconcile missing friends; a partial result keeps cached
omissions.

`join-instance` checks, in order: request shape (target ids up to 2,048 chars), the
`allowJoinInstances` setting (`joining-disabled`), main's current location for the friend
(`unknown-friend`, `stale`), `isFriendJoinable` (`not-joinable`), `expectedTarget` against the
current target (`target-changed`), `adapter.buildJoinUrl` passing `isAllowedLaunchUrl`
(`invalid-url`), a [`JoinCoordinator`](../src/main/services/joinCoordinator.ts) permit with one
launch per platform at a time and a 3 s destination and friend cooldown (`cooldown`), and finally
[`GameHandoff.deliver`](../src/main/services/gameHandoff.ts): launch through `shell.openExternal`
(`launch-failed`), or reach the game that is already open (VRChat URL pipe, else one
`adapter.selfInvite`, `invite-failed`). The account fence is checked again after every wait,
including right before the pipe write (`stale`). Success carries `handoff`. Denial logs carry platform and
reason only. `join-explore-room` shares the same coordinator, launch validation and hand-off
(`ExploreServiceOptions.deliverJoin`).

Linked-profile lease: [`links.ts`](../src/main/ipc/links.ts) issues a random lease that rotates
whenever either platform's `AccountSession` resolution changes. A snapshot holds only profiles
with a member owned by a currently ready account, plus `accountIds` for those ready accounts.
`change-linked-profile` validates strictly (ids match `[A-Za-z0-9_-]+`, names up to 256 chars,
shared note up to 500 chars after trimming), returns `stale` for an old lease, requires one
friend per platform with both accounts ready for `replace` (`unavailable`), qualifies members
with main's account ids, and applies through
[`LinkGraphStore`](../src/main/services/linkGraphStore.ts) with revision checks. Failure reasons
are `invalid`, `stale`, `unavailable`, `storage` and `rate-limited`.

## 3. Live adapter events (`AdapterEvent`)

[`AdapterEvent`](../src/shared/types.ts) is the normalized live vocabulary. Each platform maps its
WebSocket wire into these events; the renderer never sees raw platform objects. Presence comes
only from this stream (VRChat Pipeline and ChilloutVR `/users/ws`), never from polling.

Main fan-out: [`wireAdapterEvents`](../src/main/adapterWiring.ts) subscribes to both adapters and
hands every event, in order, to `AppStatusService.recordConnection` (`connection` only),
`LocationAuthority.consume`, `FriendAlerts.consume`, `InboxService.consume`, and the
`friend-event` broadcast. `inbox` events go only to `InboxService` and are never broadcast, so
`FriendEvent` is built from `BroadcastAdapterEvent`. Each
consumer is isolated, so one throwing consumer cannot block the rest. The broadcast also clears
`ExploreService`, `AvatarLibraryService` and `CommunityService` for the platform on `auth-invalidated`. In the renderer,
[`useLiveFriendEvents`](../src/renderer/src/hooks/useLiveFriendEvents.ts) applies events through
[`applyFriendEvent`](../src/renderer/src/utils/applyFriendEvent.ts).

| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Rules when extending:

- Stay honest to the wire. Do not fabricate fields a platform does not send; that is why
  `friend-offline` carries only an id and `presence-snapshot` carries no profiles.
- Extend the union, `applyFriendEvent`, `LocationAuthority`, `FriendAlerts` and their tests
  together. Metadata-only events must not advance location revisions or raise alerts.
- ChilloutVR friends never carry `status`, `statusDescription` or `trustRank`, and their presence
  is only `in-game` or `offline`.
- `connection: 'live'` is not proof of authentication. Only an authenticated auth status lifts a
  renderer quarantine.

Both platforms implement [`IPlatformAdapter`](../src/main/services/adapters/IPlatformAdapter.ts).
`app.ts` creates one `VrcAdapter` and one `CvrAdapter`, keyed by platform, and passes them to IPC

Rule (auth results): a failed `LoginResult` whose path discarded local auth state carries
`sessionCleared: true`, and the renderer must set that platform's auth cache to unauthenticated.
`credential_persistence_failed` and `auth_identity_unavailable` are terminal: no identity or
pipeline is published.

Rule (identity): both adapters publish `onIdentity(null)` before an identity-clearing session
boundary and publish the account id only after auth state settles; main feeds it to
`AccountSession`. `onSessionBoundary` makes main clear `FriendAlerts`, `LocationAuthority` and
Explore for that platform and push `identity-boundary`. A VRChat data-path 401 passes
`identityRetained: true` instead: main still clears its state but sends no `identity-boundary`,
because the following `auth-invalidated` quarantines the renderer. Main's credential-store
closures ignore the `accountId` argument of `save`; there is no separate owner store (#371).

Rule (auth fencing): a later login supersedes an earlier one at its next await, explicit logout
cancels active and queued auth work, and a session that is still being saved cannot serve data.
Authenticated requests during that window throw `AuthSessionPendingError`, and the VRChat avatar
cookie reads as `null`.

### Request admission and queue

Rule: every platform HTTP request goes through `BaseAdapter` and the platform's
`ApiAdmissionController`. Never call `fetch` for a platform API elsewhere. `app.ts` creates one
controller per platform and shares it with that adapter's REST, Explore, VRChat API hops in
`AvatarCache`, and the pipeline's dial cooldown. Starts are spaced by
`API_REQUEST_MIN_INTERVAL_MS` (1 s) plus up to 99 ms of jitter. Every physical retry reacquires
admission and observes the latest shared 429 cooldown. Cancellation, queue overflow and a pending
session are control flow: stop later pages or enrichment, do not count a circuit failure, and do
not negative-cache.

## 5. Renderer

The renderer lives in `src/renderer/src`. Its contract is
[`src/renderer/AGENTS.md`](../src/renderer/AGENTS.md). Four rules apply to
every surface below:

- TanStack Query owns server and cache state. Zustand owns view state only.
  Stores never import each other.
- Every bridge consumer checks that `window.vrx` (and the method it needs)
  exists, so tests and the design guide degrade instead of throwing.
- App-wide subscriptions are mounted once. Do not add a second listener for
  an event that an app-lifetime hook already handles.
- User-facing copy goes through i18next, with the key in every locale.

Boot order: [`main.tsx`](../src/renderer/src/main.tsx) installs
`installDocumentDropGuard`, then renders `PersistQueryClientProvider`
(`buildPersistOptions`, `onPersistRestore` on restore) around the top-level
`ErrorBoundary` and `App`. [`App.tsx`](../src/renderer/src/App.tsx) mounts
`useSettingsPersistence`, `usePlatformFilterSettings`, `useApplyTheme`,
`useApplyGlow`, `useLiveFriendEvents`, `useLinkedProfileEvents` and `useActivityEvents`, calls
`notifyRendererHydrated` once settings hydrate, and routes a hot-instance
notification click (`onNavigateToDashboard`) to Hot Instances. It shows
`BootSplash` until settings hydrate, then `SetupWizard` while `setupPending`
is true, `AppShell` when either platform is
`authenticated` or `error` (or its auth check failed), `BootSplash` while
auth is still pending, and `LoginScreen` otherwise.
[`AppShell`](../src/renderer/src/components/AppShell.tsx) mounts
`useHiddenPageFallback` (a hidden active page falls back to the Dashboard
before paint), `useExploreCoordinator` and the single `JoinConfirmDialog`.

`useLiveFriendEvents` applies friend deltas through `applyOrderedFriendEvent`.
`connection: live` invalidates that platform's roster. `roster-changed`
invalidates it. Any connection change drops the buffered CVR snapshot. An
identity boundary clears VRChat replay state, the buffered snapshot and that
platform's note queries, sets the roster to `[]`, invalidates it, and persists.
`auth-invalidated` quarantines the platform: the roster is forced to `[]`,
in-flight fetches are cancelled, auth is re-checked, and every later event for
that platform is dropped. Only an `authenticated` auth-status lifts the
quarantine; socket-open is not proof of re-auth. When auth settles to a
signed-out state over a restored roster, that roster is also cleared.

`useExploreCoordinator` counts Explore as relevant while the window is visible
and either the Explore page is open or the Dashboard is open with Popular now
on. It declares the active platforms (in filter scope, signed in, with an
account ID) through `setExploreActive`. Only after main accepts does it admit
images and send `automatic` requests. A platform qualifies when its snapshot
is missing, stale or at least 60 s old, and its last automatic attempt for that
account was at least five minutes ago. Visibility, focus, `online` and
`connection: live` wake it. Identity boundaries and `auth-invalidated` clear the
gate and the platform's cache. AppShell unmount declares no platforms.

`useJoinInstance` keeps one module-level store for the whole renderer. While
any join runs, `isJoining` disables every Join control. It returns `join`,
`joinExplore`, `confirmPending(mode)`, `cancelPending`,
`acknowledgePendingTarget`, `invalidatePending(platform?)`,
`invalidateFriendPending`, `joinFailedFor`, `joinFailureFor` and
`joinExploreFailureFor`. With `allowJoinInstances` off, a join shows
`joining-disabled` feedback and sends nothing. With `confirmJoin` on, a join
parks the reviewed target for `JoinConfirmDialog` instead of launching; a
second join while one is parked is ignored. Failure feedback stays until the
next attempt or a boundary. Rule: send main only a friend ID with the expected
target, or a main-issued Explore `selectionRef`. Main decides joinability and
builds the URL. Nothing retries automatically.

## 6. Main process

Main owns the privileged side of VRX: windows, credentials, sessions, platform
traffic, persistence, alerts and game launches. [`index.ts`](../src/main/index.ts)
takes the single-instance lock and only then imports
[`app.ts`](../src/main/app.ts), the composition root. `app.ts` builds one
`ApiAdmissionController` per platform, both adapters, the services below, the
IPC handlers, the window, the tray and the updater, and disposes them on
`before-quit`. The method contract every adapter implements is in
[section 4](#4-platform-adapter-contract); renderer-facing handlers are in
[section 2](#2-ipc-channels).

`UpdaterService` follows the saved `updateChannel` (`updateFeed.ts`). Stable
uses electron-updater channel `latest` with `allowPrerelease` and
`allowDowngrade` off, so it never receives a beta, dev, or rc build. Beta
and dev turn `allowPrerelease` on and leave `allowDowngrade` off.
electron-updater already promotes its beta channel to a newer stable release.
It only promotes the built-in alpha and beta channels, so dev uses
`installDevStablePromotion` (`devReleaseFeed.ts`): that resolver walks the
GitHub release list and `selectReleaseVersion` picks the greatest stable or
`-dev.N` that is newer than the running build. A beta build is never a dev
candidate, and an older release is never selected on any channel, including
right after a channel change. Assign `allowDowngrade` after `channel`,
because that setter forces downgrades on, then set it off again. A version
outside the selected channel is ignored. Changing channel cancels an in-flight download and waits
for that attempt to settle before the next check, so electron-updater cannot
hand back the previous download. A disallowed build that was downloading or
staged will not install on quit, and a late download event for one cannot
install or replace an allowed offer. An installed beta or rc build stays on
stable until the user picks a channel. electron-updater diagnostics are
discarded rather than logged.

## 8. Design guide fixtures (`docs/guide`)

`docs/guide` is a documentation-only browser build. It renders production
renderer components, CSS, fonts and translations with synthetic data. None of
its exports are application APIs, and it adds no IPC channel, account
capability or application hook. Its contract is
[`docs/guide/AGENTS.md`](guide/AGENTS.md).

- [`design.html`](design.html) loads `guide-entry.tsx`, the human guide.
- [`glass.html`](glass.html) loads `scene-entry.tsx`, which hosts one scene.
- Scripts: `npm run guide:dev`, `guide:typecheck`, `guide:build` (output in
  `dist/design-guide`) and `guide:preview`.

How a scene loads: `glass.html?scene=…` without `render=1` draws the scene
frame (theme, glow, state, grayscale, background picture and reset controls, plus the source
revision) around an iframe. With `render=1`, `scene-entry.tsx` installs the
fixture bridge first, then imports `scene-renderer.tsx`, so no connected
component module runs before the fake bridge is sealed. The guide applies the
theme with the production `applyTheme`; scenes call `useApplyTheme` and
`useApplyGlow`. `production.css` imports the shipped `main.css` and scans the
renderer source for classes. Vite aliases `@renderer` and `@shared` to the
production source.

Isolation rules contributors must honor:

- Never touch real accounts, credentials, persistence, network, external
  images, game launches or updater actions. Fixture callbacks change synthetic
  memory only. `fixture-bridge.test.ts` checks this.
- Import production components, tokens, copy and fonts. Do not copy markup or
  CSS into the guide, and do not change production UI to make a scene easier.
- Keep seeded query data for the scene document's lifetime. Add no polling,
  refetch or timers that start work.
- A guide-owned overlay that takes focus opens only after reader input and
  returns focus to its opener (the drawer and join scenes open from a button).
- Label each example as a static sample, interactive fixture or proposal, and
  keep guide controls outside the app examples.
- Dark is the default scene. Check light parity, and keep the 900×670 desktop
  floor; let the guide scroll rather than hide controls.
- Keep guide source and output out of packages. `electron-builder.yml`
  excludes `docs/guide/**`, `docs/design.html`, `docs/glass.html` and
  `dist/design-guide/**`, and the renderer entry never imports `docs/guide`.
- When the bridge type changes, update `createFixtureBridge` in the same PR;
  `npm run guide:typecheck` fails until it matches.
